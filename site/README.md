# Pane 官网（site/）

Magpie 式零框架单文件官网：页面使用静态 HTML 与 vendored 第三方库；交互演示由主项目前端构建。`public/index.html` 为中文源页面，Worker 将 `/en`、`/en/` 映射到同一页面，由 `site.js` 应用英文词典；`/?lang=en` 也可进入英文页面。

- 本地预览：`cd site && npx wrangler dev`（127.0.0.1:8787，`/` 中文、`/en/` 英文）
- 测试：`node --test site/*.test.mjs`（资源与链接、演示源码哈希、目录计数、中英文刷新间隔、英文路由及下载回退；node 22+，零依赖）
- 部署：push main 且仓库变量 `SITE_DEPLOY=true` 时由 `.github/workflows/site-deploy.yml` 跑 `wrangler deploy`；secrets 为 `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID`
- 搜索与分享信息：中文标题、description、canonical、Open Graph 与 Twitter Card 写在 `public/index.html`；英文标题与 description 使用 `i18n.js` 的 `metaTitle` / `metaDescription`，Worker 在英文入口的初始 HTML 中替换对应字段，`site.js` 同步浏览器中的字段。官方地址统一为 `https://pane.threetwoa.live`，英文 canonical 为 `/en/`。
- 换截图：同名替换 `public/img/` 下 `overview / spend / heatmap` 的 `-dark.png` 与 `-light.png`（尺寸按 `<img>` 的 width/height），零代码改动
- 加语言 checklist：`i18n.js` 顶部注释（字典 + LANGS + 页面语言菜单 + T() 参数）
- **Hero 手绘高亮**：标题的「调用 / 看得见」标注由 rough-notation（`public/vendor/rough-notation.js`，MIT, Preet Shihn）绘制，算法与配色沿用 Magic UI Highlighter 组件（underline `#FF9800` / highlight `#87CEFA`，源码与许可归档在 `vendor/magicui-highlighter/`）。标注配置写在 `index.html` 的 `data-hl-*` 属性上（type / color / stroke / padding），绘制与重画逻辑在 `site.js` 的 `initInkMarks()`：等 hero 入场动画结束、Web 字体加载完成后绘制，resize 时重画，`prefers-reduced-motion` 时瞬画无动画。新增标注点只需加一个带 `data-hl-*` 的 `.ink-mark`。
- **品牌文字页脚**：保留 Ruixen Wordmark Footer 的入场与光标追光（原作与 MIT 许可归档在 `vendor/ruixen-wordmark-footer/`），字形改为自绘的 `public/pane-wordmark-pixel.svg`：5×7 点阵、阶梯轮廓，不依赖额外字体。`.wf-word` 用 SVG mask 填充主题色金属渐变，宽度为 84vw、上限 1260px；下载区底部淡出到 `--bg`，字标背景的青蓝光晕由透明渐入后再淡出，去掉交界硬线。深浅主题都使用 `--ink` / `--bg`，光标追踪与 reduced-motion 行为沿用 `initWordmarkFooter()`。字标必须留在 `.footer-content` 之外，避免英文链接的位置映射错位。
- **分组 FAQ**：`#faq` 按主题分 3 组 × 3 条，设计取自 Ruixen UI 的 Grouped FAQ Section（源码与 MIT 许可归档在 `vendor/ruixen-grouped-faq/`）。关闭态只有一条细下边框；打开态「抬起」成卡片（`--surface` 底 + `box-shadow:0 0 0 1px var(--line-strong)` 描边 + 12px 圆角 + summary 下边框转透明）。描边用 ring 而非 border，开合不重排；阴影只在亮色主题加（站点所有阴影都是写死黑色，暗色下不可见，暗色靠描边抬起）。展开动画用 `grid-template-rows: 0fr → 1fr`（内容包在 `.faq-body` 里，它同时是裁剪层），`visibility` 延迟切换保证关闭态答案仍离开无障碍树；`prefers-reduced-motion` 下无过渡。英文文案在 `site.js` 里按组/条目位置取键（`faq.q{组*3+条}`，组标题 `faq.g{n}`），不再依赖扁平下标数组。**i18n 说明**：字典键仍由 JS 选择器应用，页面没有 `data-i18n` 标记，所以 `site.test.mjs` 的 i18n 双向 parity 校验依旧空转（要启用需把全站文案迁到 `data-i18n`，属独立改动）。
- **Hero 标题楷体**：标题用系统楷体栈（`STKaiti` 华文楷体 / `KaiTi` 楷体 / `Kaiti SC`，`serif` 兜底），不加载任何 Web 字体——macOS 与 Windows 都自带楷体，零字体包负担。换字体栈只动 `.hero-title` 的 font-family。
- **动态网格背景**：全局 `#grid-bg` 是 Magic UI Animated Grid Pattern 的移植（原组件源码与 MIT 许可归档在 `vendor/magicui-animated-grid-pattern/`），用站点已 vendored 的 GSAP 驱动（零新增依赖）。参数写在 `index.html` 的 `data-grid-*` 上（`size/squares/max-opacity/duration/repeat-delay`，对应原组件 props），驱动逻辑在 `site.js` 的 `initGridBackground()`：SVG pattern 画网格 + 随机方块做 `opacity` 呼吸（`repeat:1 + yoyo` ≡ 原版 `repeatType:"reverse"`，完成后随机换位重跑）。配色走主题变量（网格线 `--line-strong`、方块 `--accent`），主题切换无需重初始化；`prefers-reduced-motion` 与 ≤720px 视口只保留静态网格（不渲染方块）；GSAP 缺失时同样降级为纯网格。方块密度上限与淡出 mask 见 `.site` 的 `#grid-bg` 规则。
- **Demo 悬浮板跟随当前窄窗布局**：直接打包主项目的 `src/`，不维护另一套图表。iframe 内部视口为 439×640，落在 `src/styles.css` 的 ≤440px 断点内，让圆环在上、模型列表在下；预留 1px 避免浏览器缩放的断点舍入误差。外层 `.demo-desktop` 用 `--wf-width` 与 `--wf-scale` 缩放展示（默认 .90205、1050px 档 .75171、720px 档 .72893），展示宽度仍约为 396/330/320px。配置使用 regular 密度和 MV Boli 字体；模型 Token 比例及首行额度按用户提供的悬浮板截图更新，美元金额仍为示例值。`site.test.mjs` 校验 `demo/source.json` 的源码哈希，主项目变更后需重跑 `node site/scripts/build-demo.mjs`。
- **Demo 面板常驻渲染**：`public/demo/` 由 `scripts/build-demo.mjs` 从主项目 `src/` 构建（改主项目后重跑 `node site/scripts/build-demo.mjs`，构建完清理未被新 `index.html` 引用的旧 hash 资产——注意 `aurora-*.webp` 是被 JS 而非 HTML 引用的，别当孤儿删）。构建时有三处 demo 专属处理：① `renderChunk` 把 app 里的 `document.hidden` 读取替换为 `false`；② `transformIndexHtml` 注入一段内联 shim，**无条件**把 `requestAnimationFrame` 改道到 `setTimeout`，并在加载后若卡片区仍是静态骨架就补点一次刷新；③ `bridge.ts` 里只把**有示例数据的服务商**放进 snapshots（`enabledIds.filter(id => snapshotDefs[id])`），否则目录里新增但没有示例数据的服务商会被渲染成「无用量数据」的空卡，面板看起来完全不像真实窗口（桌面版会隐藏无凭据的服务商）。前两条缺一不可：demo 嵌在官网 iframe 里，宿主标签页在后台（或 ZCode 应用内浏览器 pane 失焦）时 guest 文档常为 hidden——hidden 文档的 rAF 被挂起，而 app 的渲染排在 rAF 里且带 `renderFrame` 去重标志，一次错过的原生 rAF 会把标志永置，面板就永远停在 `demo/index.html` 的静态骨架上（数据照常刷新、时间戳会走，但卡片不画，**连手动点刷新也救不回来**）。改道必须无条件：shim 若按 `document.hidden` 判断，会因「宿主可见性在 iframe 加载前后翻转」的竞态而跳过，首屏照样卡死。代价是真实浏览器里 rAF 也走 16ms `setTimeout`（功能不受影响，非 vsync 对齐）。`bridge.ts` 的 `fetch_usage` 也不加假延迟，保证首屏即时呈现。
