设计档位对比

最后更新：2026-10-26 · 契约权威：site/DESIGN.md · 本页不对外索引

#83 要求把「整理 / 升级 / 重塑」三条路径写清楚，再由仓库所有者选定一档，作为所有站点 UI 票（#84–#89）的验收基线。下面是三档的实际差异与成本。

档位一 · 整理ORGANIZE已选定
目标现有骨架不动，把已经长出来的样式、动效与文案收敛成一套可验收的契约。
会改token 单一来源与禁用清单；section index 作为唯一编号系统；信任三卡与 stat-row；动效分级（入场/反馈/叙事）与 reduced-motion 终态；comic-pixel 皮肤限定在 opt-in 属性内；i18n 双向锁与死键检查；版本与 provider 计数改为生成。
不改hero 结构、demo 舞台几何、注释锚点坐标系、下载区主行动、现有栅格。
成本约 2–3 天，已在 0.11.0 落地大部分。
风险低。改动集中在契约与测试，视觉只有局部收敛，回归面小。
档位二 · 升级UPGRADE
目标保留信息架构，替换视觉语言：新的排版尺度、卡片体系与配色层级。
会改type scale 与字重层级重做；卡片改为双层（容器 + 内容）；引入语义色板扩展；hero 与 demo 舞台重新排版。
不改页面顺序、section 数量、demo 交互模型、法务与下载路由。
成本约 6–9 天，含三皮肤/明暗/四宽度全量回归。
风险中。demo 注释锚点依赖舞台几何，重排会连带改 site.js 的碰撞避让与连接线计算。
档位三 · 重塑REBUILD
目标换叙事结构：从「功能罗列」改为「一次刷新的旅程」，页面顺序与章节全部重写。
会改信息架构、章节顺序、hero 主张、demo 的位置与角色、滚动叙事（#87）成为主干而非点缀。
不改后端契约、法务事实、下载路由。
成本约 2–3 周，且需要 owner 多轮手感验收。
风险高。现有 i18n 键、测试锁与注释锚点几乎全部失效，等于重做站点并重新验收。

决定

2026-10-26，仓库所有者选定 档位一 · 整理。理由：站点的事实层（版本、计数、平台矩阵、隐私与法务）刚刚被测试锁定，此时换视觉语言会把刚建立的验收基线全部作废；#87 的滚动叙事作为「整理」档内的一项动效收口，不需要重塑信息架构。

后续若要走档位二或三，先更新 site/DESIGN.md 的契约与本页决定，再动代码——契约先于实现。

整理档在 0.11.x 的落点

  • 契约与禁用清单：site/DESIGN.md §2–§4、动效与字号层级 §9、法务页规则 §10。
  • 信任与规格：边界三卡 + stat-row + hero-meta + 免责句（#84），英文文案随 /en/ 同步。
  • 动效：count-up、磨砂导航、标签打字、POP、文字揭示（#86）；滚动叙事与共享 ticker（#87）。
  • 皮肤：comic-pixel 只在 html[data-site-skin=comic-pixel] 下生效（#89）。
  • 口径：版本与 provider 计数由 site/scripts/sync-site-version.mjs 生成，CI 以 --check 把关（#79）。
