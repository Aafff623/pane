# Pane 落地页设计规范

适用于 `site/` 下的营销页面：首页、`/demo/`、`/privacy/`、`/terms/`，中英两套路由。

**不适用于**桌面应用面板和设置界面——那是 [`docs/desktop-ui-conventions.md`](../docs/desktop-ui-conventions.md)。两套界面服务不同场景：落地页一屏讲一件事，面板一屏装几十个服务商的数据。把它们统一成一套字号和留白标准会毁掉其中一个。

## 一、设计基调

参考苹果官网的极简：大量留白、克制的色彩、靠排版而非装饰建立层级。一屏一个主张，不是一屏塞满功能。

## 二、色彩

### 90 / 10
大约 90% 的面积是中性色（`--background`、`--card`、`--foreground`、`--muted-foreground`、`--border`），10% 是单一强调色 `--primary`。

强调色只用于：**一个主行动按钮**、**一个关键数字**、**当前导航项**。不要用它做装饰性线条、背景块或图标着色。

### 只用 token，不写字面色值
现有 token（`src/styles/globals.css`）已经处理了明暗两套：

| 用途 | Token | 浅色 | 深色 |
|---|---|---|---|
| 页面底色 | `--background` | `#f9f9f9` | `#08090a` |
| 正文 | `--foreground` | `#0a0a0a` | `#eef1f2` |
| 次要文字 | `--muted-foreground` | `#666666` | `#9ba3a8` |
| 强调 | `--primary` | `#087d6d` | `#64d7c2` |
| 边框 | `--border` | `#dedede` | `#242a2e` |

### 允许的例外
- **品牌插画和产品截图**（`hero.module.css` 里的暗角、`panel-stage` 的点阵底纹）——这是产品展示的一部分，不是装饰性渐变。
- **图表和环形进度**的渐变——数据可视化语言。
- 深色主题下 hero 的暗角需要加深，否则截图会浮在纯黑上。

明确禁止：装饰性的彩色渐变块、霓虹光晕、多色阴影。

### 字重与明度
标题用 `font-semibold`（600）配 `--foreground`；正文 `font-normal`（400）配 `--foreground` 或 `--muted-foreground`。对比来自字重和明度，不来自字号跳级。

## 三、字体与字号

### 现状是 Inter，不是 Geist
`src/app/layout.tsx` 用 `next/font/google` 加载 Inter，暴露为 `--font-inter`。要换成 Geist 是一次真实的替换：改 import、改 CSS 变量、重新确认中亚欧字符的回退。

**换之前先确认值得。** Inter 和 Geist 在这个体量上视觉差异很小，但换字体要重新检查每一处的换行和行高。

### 字号阶梯
现有页面实际用的：

| 用途 | Class | 实际 |
|---|---|---|
| 正文 | `text-base` | 16px |
| 次要正文 / 导航 | `text-sm` | 14px |
| 极小标签（eyebrow、徽标） | `text-xs` | 12px |
| 区块标题 | `text-3xl md:text-4xl lg:text-5xl` | 30 / 36 / 48px |
| 首屏标题 | 同上，走 `HeroHeadline` 分段动画 | — |

**正文最小 14px，不用 12px 做正文。** 落地页的读者在手机上阅读，不是在看数据密集型面板。

### 间距
Tailwind 默认栅格是 4px，`p-4` = 16px。现有页面遵循这个栅格，保持一致即可，不需要额外发明。

留白要比面板大方。区块间距 `py-14 md:py-20`（56 / 80px）是现有节奏，不要压缩。

### 圆角
按尺寸分档，不要混用：

| 元素 | 圆角 |
|---|---|
| 小按钮、徽标 | `rounded-md` / `rounded-lg`（6 / 8px） |
| 卡片 | `rounded-xl`（12px） |
| 大容器、demo 外框 | `rounded-2xl`（16px） |
| 头像、圆点 | `rounded-full` |

## 四、布局与内容

### 一屏一个主张
每个区块只承担一件事。首屏是"这是什么"，解剖区是"长什么样"，工作流是"怎么用"，信任区是"安不安全"，下载区是"怎么装"。

### 层级靠排版，不靠解释文字
区块开头用统一的三行结构：eyebrow（`text-primary text-sm font-medium tracking-wider`）→ 标题 → 一句话描述。这是全站唯一的"标题 + 描述"模式，保持一致。

**不要在一个区块里再套 subsection 的标题 + 描述。** 需要解释时，用一张图、一个对比或一个具体的例子，不是再加一段话。

### 禁止嵌套卡片
一张卡片里不再套带边框的卡片。`demo-embed.tsx` 现在的结构是 `rounded-2xl` 外框 → 顶栏 → 内层 `rounded-xl` 嵌 iframe——这是**唯一允许的例外**，因为内层是产品截图的画框，不是内容卡片。

新增区块时，需要"分组"就用间距和标题，不要加边框。

### 文案必须可核实
页面上的每个数字和事实都要能对到代码或仓库：

- `src/content/facts.ts` 的 `version`、`providers` 由测试绑定到 `package.json` 和 `src/providerCatalog.ts`
- "WinGet 审核中"是 PR 状态，不是"已上架"
- macOS 标 Beta，因为构建矩阵里有但它不是主要验证平台
- 不要写"绝对安全""零风险"——隐私页列了每一次出网请求，用可核实的话替代绝对化表述

## 五、中英双语

两套消息树（`src/components/i18n.ts`）的 key 必须一一对应，且**含义对等**。不是逐字翻译。

现有测试绑定：
- key 数量一致
- 每个页面的 `og:`/`twitter:` 元数据用它自己的语言（英文页不能出现中文分享卡）

改文案时两边都要改。只改一边会让另一个语言出现旧内容。

## 六、交互

### 按意图显示
次要操作在悬停、聚焦或滚动进入时出现。已实现：导航的移动端菜单、demo 的"新窗口打开"按钮。

### 首屏动画
`HeroFilm` 是产品演示动效，由 `pane-motion` 驱动。必须尊重 `prefers-reduced-motion`——现有实现已处理，新增动效时照做。

### 演示 iframe
`PaneDemoFrame` 负责主题同步（跟随页面明暗）和语言。高度用 `min(660px, calc(100dvh - 13rem))` 并带 `min-h`，因为面板内部滚动，固定高度会在手机上裁掉内容。

## 七、渲染验收

**以浏览器真实画面为准。** 类型检查和静态导出通过，不能证明页面是对的。

这轮踩过的坑：

| 现象 | 为什么查代码发现不了 |
|---|---|
| 英文页发出中文分享卡 | Next 元数据浅合并，页面只覆盖 `title` 时继承 layout 的中文 OG |
| iframe 在手机上裁掉一半 | `h-[660px]` 语法正确，只有真机看才发现 |
| 分享卡语言不一致 | 构建产物 `<head>` 里才有答案，源文件里看着没问题 |

**验收清单：**

1. `npm run build` 通过（静态导出到 `out/`）
2. `npm test` 通过（含分享元数据语言一致性、demo 来源哈希）
3. 起一个静态服务打开 `out/`，**不能只看源码**
4. 覆盖 1440 / 768 / 390 三个宽度
5. 中英两条路径各走一遍：首页 → 演示 → 下载 → 法务页
6. 明暗两套主题各看首屏和演示区
7. `prefers-reduced-motion` 下首屏动画降级

## 八、明确的取舍记录

- **字体**：现在是 Inter。换 Geist 是一个选项，但需要重做换行与行高校验，收益有限。
- **图标**：现在是 `lucide-react`（13 个图标，8 个文件在用）。Reicon 是 MIT 的替代品，换成它需要重画图标资产并保持 1.5px 描边一致——不影响功能，属于纯视觉替换，优先级低。
- **单色规则**：不追求字面上的"90% 中性色"，而是保证强调色**在需要的地方才出现**。品牌插画里的颜色是产品展示，不计入这个比例。
