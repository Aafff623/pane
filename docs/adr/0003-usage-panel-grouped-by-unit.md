# ADR 0003 — 用量面板按计量单位分组，不按业务分类

- 状态：已接受（2026-10-11）
- 决策人：仓库所有者 Aafff623

## 背景

「总花费」面板此前只有一种计量口径：每个 provider 的每条记录都同时带
美元和 token（`ProviderSpend` 的 `cost` / `tokens`），而 credits 被**故意
排除**在外——`spend.rs:4697` 的原话是 credits *"cannot be converted into
tokens or dollars honestly"*。现在要把这个面板的口径扩到其他计量单位
（积分、分钟等），于是必须先回答一个问题：**面板按什么分组？**

两个候选：按**计量单位**（token / 积分 / 分钟…），或按**业务分类**
（已存在的 `Coding | Productivity | Mcp`）。

## 决策

用量面板**按计量单位分组**，业务分类只作为其下的第二轴。

1. 顶层是**单位分节**（token / 积分 / 分钟）竖排，每节一个图 + 明细；
   **没有跨单位总数**——单位之间不可通约，"总用量"没有意义。
2. 只有 **token 允许跨厂商相加**（拼同一张饼图）；**积分、分钟按「家」
   分开**——不同厂商的"积分"是各自的内部货币，不可通约。
3. 一张卡可以同时挂多个单位（闪电说 = 分钟 + 积分），**各归各节**，
   不折算、不合并。
4. 成员判定：**能给出该单位「绝对量」的 provider 才进**（来源可以是本地
   台账，也可以是服务端快照）；只报百分比、给不出绝对量的 provider 归
   「额度总览」，不进用量面板。
5. 数据来源分两类并明确标注：**本地台账**（有逐日趋势/热力图）与
   **服务端快照**（只有当前值，无历史）。
6. 「总花费」这个概念随之改名为「**用量**」；**美元不是独立单位，是 token
   的一个视图**（沿用现有的圆环口径切换）。

## 后果

- 面板语义从"花了多少钱"变成"各计量单位消耗了多少"；"总花费"这个名字
  会误导，必须改。
- 需要 `CONTEXT.md` 显式定义 **额度 / 用量 / 计量单位** 三个词，并声明
  "同名单位在不同厂商之间未必可通约"。
- 代码层：单位目前是以自由文本散在 metric 的 `label`/`detail` 里的，全仓
  **没有单位枚举**；要落地这个分组，得先把单位变成显式的、可判定的值。
- 「额度总览」不受影响，仍是独立的一节（它回答"还剩多少、何时重置"）。

## 否决的替代

- **按业务分类分组**：生产力类目前只有 **1 家**（闪电说），MCP 类 4 家，
  切到这两类时饼图只剩一个扇区，毫无意义；而业务分类本身可以嵌在单位
  之下当筛选，反过来做不到。
- **把 credits / 分钟折算成美元或 token 以统一口径**：`spend.rs` 已明确
  判定这是"不诚实的换算"，是当初把 credits 排除出 `ProviderSpend` 的
  原因；重新引入等于推翻那个判断。
