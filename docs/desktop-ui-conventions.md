# Pane 桌面端界面约定

描述性的，不是规定性的。这份文档记录 Pane 面板和设置界面**现在实际遵守什么**，以及在改动前必须知道哪些约束会被破坏。新写界面时照这个来；想突破其中某条，先想清楚它护着什么。

落地页是另一套语言，见 [`site/DESIGN.md`](../site/DESIGN.md)。不要把落地页的留白和字号搬到面板上。

## 一、这个界面的物理条件

先把尺子摆出来，因为后面每一条都是从它推出来的。

| 事实 | 值 | 位置 |
|---|---|---|
| 面板默认尺寸 | 980 × 700 | `src-tauri/src/lib.rs` `PANEL_DEFAULT_SIZE` |
| 面板最小尺寸 | 860 × 620 | 同上 `PANEL_MIN_SIZE` |
| 界面缩放 | `body.ui-scaled { zoom: var(--ui-scale) }`，80%–175% | `src/styles.css` |
| 正文实际字号 | **11、12、12.5px 为主**（287 处），10px 用于极小的辅助标签 | `src/styles.css` |
| 按钮足迹 | 26px，圆角 `--radius-btn` 9px | `src/styles.css` |
| 卡片圆角 | 14px | `.card-panel` |
| 文本色 | `--foreground`（暗 `#d4d4d4` / 浅 `#333333`） | 主题变量 |
| 次要色 | `--muted-foreground`（暗 `#9d9d9d` / 浅 `#6f6f6f`） | 主题变量 |
| 强调色 | `--primary`（暗 `#007acc` / 浅 `#0066b8`） | 主题变量 |

**这是一扇常驻的悬浮窗，不是网页。** 用户会在 980px 宽里同时看几十个服务商的额度、余额、重置时间和用量条。任何"放大留白""字号提到 16px"的改动都会直接减少一屏能装的信息量——这是产品定位问题，不是审美问题。

## 二、颜色

### 只用变量，不写字面色值
所有颜色走 `var(--…)`。硬编码的十六进制在暗色主题下会直接不可读，在皮肤下会突兀。

```css
/* 对 */  color: var(--muted-foreground);
/* 错 */  color: #6a6a6a;
```

例外只有一处：数据系列的分类色（`--stats-c2`…`--stats-c6`）保留独立色相，因为相邻两条曲线必须能分辨。`--stats-c1` 跟随 `--primary`。

### 强调色是稀缺资源
`--primary` 用在：当前选中项、主操作按钮、关键数字、焦点环。其余一律中性色。密度上，一屏里强调色覆盖面积应明显小于中性色——不是为了满足比例，而是强调色一多就不再是强调。

### 三款官方皮肤改的是配色而不是结构
`ink`（山水笺）、`signal`（像素分镜）、`comic-pixel`（漫画像素）通过匹配类名重绘：`.provider-help`、`.ph-head`、`.tabs`、`.tab`、`.panel-nav-item`、`.toggle input[type=checkbox]` 等。

**这意味着：改标记或改类名会静默地让皮肤失效。** 迁移组件时保住的不是"看起来一样"，是这些选择器还能命中。

## 三、字号与间距

### 不要统一到一个字号
11、12、12.5px 的分层是排版调试的结果，不是随手写的。层级靠**字重 + 明度**区分，不靠字号跳级：

- 标题：字重 600，`var(--foreground)`
- 正文：字重 400，`var(--foreground)`
- 辅助：字重 400，`var(--muted-foreground)`

### 4px 栅格是参考，不是铁律
大部分间距是 4 的倍数，但存在 3、5、7、9、11、13px——这些通常出现在紧贴文字的行高和内边距上。把 11px 改成 12px 会改变整张卡的视觉节奏。

改间距时优先用现有 token，没有合适的再加，不要为了"对齐 4px"去动已经调好的值。

### 圆角按尺寸分档
| 尺寸 | 圆角 |
|---|---|
| 按钮、输入框 | 9px（`--radius-btn`） |
| 卡片、面板 | 14px |
| 弹窗 | 16px |
| 小徽标、标签 | 6px |
| 全圆（头像一个点） | 999px |

## 四、信息密度

### 解释性文字是功能，不是负担
界面里有 122 处 hint / note / help 类文字。删之前先看它是不是在做这些事：

- 说明一次破坏性操作的后果（"删除服务商，保留用量记录"）
- 说明凭据从哪来（"从本机 Claude Code 登录态读取"）
- 说明为什么某项不可用（"需要先在服务商侧开通"）

**这些不是"次级描述文字"，是安全信息。** 落地页的"禁止副标题"规则不适用于这里。

### 嵌套要克制，但表格类数据允许分隔
卡片里不再套带边框的卡片。但以下结构是合法的，不要为了"扁平"拆掉：

- 额度环 + 数字 + 进度条（三个元素同属一个数据点）
- 账号行（`card-account-tab`）之间的分隔
- 设置页的分组标题

判据：**这段边框是否在表达一个独立的数据单元？** 是就留，只是"装饰性容器"就删。

## 五、交互

### 按意图显示次要操作
次要操作不该和主要数据抢位置。Pane 现在用的是**分层可见**，不是彻底隐藏：

| 状态 | 表现 | 例子 |
|---|---|---|
| 常驻安静 | `opacity` 降到 0.6–0.75，仍占位、仍可点 | `.share-btn`（0.72） |
| 交互时提亮 | hover → `opacity: 1` | `.provider:hover .share-btn` |
| 聚焦即可见 | `:focus-visible` 补 `opacity: 1` + 焦点环 | `.share-btn:focus-visible` |

**为什么不做"完全隐藏"：** 键盘用户在看不见的按钮上 Tab 会迷路，而 `:focus-visible` 只在按钮已可获得焦点时才生效。降到安静透明度既保住了视觉层次，又留住了可发现性。

新加次要按钮时用这个三档，不要默认 `opacity: 0`。

### 弹窗生命周期的唯一入口
所有模态走 `src/ui/dialogShell.ts`：

```ts
const shell = mountDialogShell({ overlayId: "x", onClose: ... });
```

它负责：焦点陷阱、焦点归还、背景滚动锁定（引用计数）、IME 提交键防护、Escape 只作用于栈顶。

**两条容易踩的：**

1. **靠 `onClose` 收尾。** Escape 走外壳的 `close()`，不经过弹窗自己的按钮处理器。任何"清除状态 / 记录版本号 / settle Promise"都必须挂在 `onClose` 上，否则按 Escape 时不会发生。
2. **`canClose` 只拦 Escape 和背景点击**，直接调 `close()` 的按钮绕得过去。需要拦住按钮时，按钮自己判断。

### 焦点必须移进弹窗
挂载后调 `shell.focusFirst(...)`。陷阱只在弹窗首尾拦截，焦点留在背景上时陷阱形同虚设，Tab 会走到弹窗后面的页面。

### 桌面端多级菜单的延时要到位
适用于**悬停展开**的菜单。Pane 目前没有这种菜单：分组菜单、设置导航、分享范围菜单都是点击展开、选完即关，所以下面三条暂无落点。将来若改成悬停展开，需要补：

- **开启延时**：悬停约 120ms 才展开，避免划过时乱闪
- **关闭延时**：移出后约 200ms 再收，给回移留余量
- **安全三角区**：从父项移向子项时，以当前光标位置和子菜单上下边缘连成三角形，光标在三角形内时保持子菜单打开

这条记录的是**为什么现在没有**，不是漏掉的待办。改成悬停式之前，先确认它比点击式更好——点击展开对键盘用户更直接，也不需要三角区。

## 六、渲染验收

**以真实画面为准，不以代码计算值或类型检查为准。** 这一条排在这里是因为它比上面所有条目都容易违反。

这轮踩过的坑，每一个都能通过 `tsc` 和单元测试：

| 现象 | 根因 | 为什么查代码发现不了 |
|---|---|---|
| A–Z 索引排成一行 | `grid-auto-flow: column` 只生成一列轨道 | CSS 合法，计算值也"对" |
| 弹窗变窄时名字被截断 | `#confirm-box` 的 ID 选择器压过 `.picker-box` | 两条规则都合法，只是优先级 |
| 间距在 420/700/900px 恒定不变 | `cqi` 相对祖先解析，不是自身 | 语法完全正确 |
| 一次 Escape 关掉两层弹窗 | `stopPropagation()` 不拦同一节点上的其他监听器 | 事件对象的行为，不体现在代码里 |
| 页面关闭后不能滚动 | 两层锁用"保存/恢复"，内层把 `hidden` 写回去 | 单层测试全绿 |

**验收清单：**

1. `pnpm build` 通过（tsc + vite）
2. 在 `temp/scripts/restart-pane-dev.ps1` 启动的真实面板里操作
3. 至少覆盖：默认宽度 + 最小宽度、默认缩放 + 一个非默认缩放、浅色 + 深色、原生 + 一款官方皮肤
4. 键盘走一遍：Tab 到每个控件、Escape 逐层关闭、焦点回到触发按钮
5. 中 / 英 / 俄三种语言各看一处长文案

**界面验收由项目所有者本人完成。** 交付时给构建证据 + 一张验收清单，不要用"代码看起来对"代替真实画面。

## 七、不要做的事

- 不要把落地页的字号、留白、单色规则套到面板上
- 不要为了"统一"改掉已经调好的 11px / 12.5px
- 不要删除解释性文字（除非确认它不是安全提示）
- 不要改名或重构标记结构而不检查皮肤选择器
- 不要硬编码颜色
- 不要在没在真实窗口里看过的情况下宣布"界面已完成"
