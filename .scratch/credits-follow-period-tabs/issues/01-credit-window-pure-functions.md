# 01: 抽纯函数：积分日差与窗口求和（先红后绿）

**What to build:** 把积分账本的「日差计算」和「按窗口求和」抽成不读文件、可直接断言的纯函数，让后续「积分跟随时段 tab」有可测的地基。这一票不改变用户可见行为（面板上积分小节的样子与今天一致），交付物是**能被 parse-tests 覆盖的纯逻辑 + 覆盖它的测试**。

**Blocked by:** owner 拍板 spec 文末两条（多账号是否合并、「全部」窗口口径）

**Status:** needs-info

- [ ] 日差计算（相邻读数差分、mid-day 重置叠加）抽成纯函数，语义与现状完全一致，既有行为不回归
- [ ] 窗口求和抽成纯函数：入参 = 账本条目 + today，出参 = 今天 / 昨天 / 7 天 / 30 天 / 全部 五个窗口的合计
- [ ] 窗口边界与 today 的口径与面板其他行（token / 美元）一致（本地日；7 天 / 30 天为滚动窗口）
- [ ] 测试覆盖：五个窗口求和；今天 0 而昨天 >0 的边界；0 消耗不产生行；**单读数无基线 → 各窗口全 0（并注明这不是回归）**；同一 provider 两个卡 id 互不串行
- [ ] 测试形态对标同文件 `credit_trend_for` 的既有用例（固定账本条目 + 固定 today → 断言数字）
- [ ] 新增测试在实现前为红、实现后转绿；不得改断言或跳过检查
