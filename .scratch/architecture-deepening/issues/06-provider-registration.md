## W2 disposition and simplification proof

Candidate: one universal key-lane transport adapter for all fetch_with_key shapes.
Burden: repeated credential/error wrapping, but vendor transport is not the same policy.
Reachability: shared key probe and scoped-account fetch are now production provider_dispatch interfaces; native dispatch is used by both global and single-card refresh and mirrored by parse-tests.
Evidence: source inventory currently38 files with fetch_with_key or snapshot_with_key (the old35 was not a stable count). Shared HTTP client, no-redirect client and bounded json_body already exist in providers/mod.rs. StepFun retries two vendor hosts but treats401/403 as final; relaybalance validates user origins then tries billing path variants and combines subscription/usage; searchquota queries pooled keys whose accounts may overlap; ClinePass maps percent-only rolling windows. Scoped Kimi/CommandCode adapters need the card id while applying provider-specific state.
Cut: moved shared orchestration/key/account identity handling to provider_dispatch; eliminated parallel global/manual native lists.
Retained: vendor-specific request/parser logic, since a universal fetch adapter needs per-vendor options/closures for the same control flow and does not retire the contract.
Consequence: no vendor protocol removed; unknown and missing-base-url input paths now have direct dispatch tests.
Proof: catalog coverage constructs/drops lazy production futures for every native registration, excludes only composite One/New API, and rejects duplicates/missing adapters. Existing provider tests retain parser and account-identity assertions.
Net effect: fewer independent registration/default/tray lists; no new universal request policy or dependency.
