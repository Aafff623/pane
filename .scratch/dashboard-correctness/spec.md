# 看板当场可见的错算与误报（dashboard-correctness）

**Status:** ready-for-agent（2026-10-23 立项，等待当前 reference-borrowings 批次收尾后开工）
**GitHub:** [#48](https://github.com/Aafff623/pane/issues/48)
**前置调研:** `temp/research/20261023-ccswitch-usage-gap.md` §9（本地不入库，含上游 release notes 原文摘录与逐条对质证据）
**分支:** 建议 `codex/dashboard-correctness`

## Problem Statement

Pane 是**托盘额度看板**：额度看许可（还剩多少、何时重置），用量看消耗（按天累积）。这两个语义是
产品本体，用户每天扫一眼就要拿结论，所以「当场看得出来」的错误等于产品失效。

对照参考项目 cc-switch v4.0.12 → v4.0.19 的 release notes（它是供应商切换器 + 本地路由网关，逐请求
明细是它的核心产品面），把两边都在做的那部分逐条回 Pane 代码对质，得到 15 条上游定点修复。按 Pane
的定位筛完，**只有 5 条构成缺陷**，其余全是账本精度——一条请求几万 token 摊在按天累积的消耗曲线上
看不出来，那些不该排进本轮，也不该排进后续。

五处缺陷的共同特征：都不是「功能不够」，而是**同一个判断在多个表面各写一遍、写漏了其中几遍**。
所以每张票的修法都要求收敛成一个共享判定，而不是在第五个地方再补一个 if。

## 已查明的事实（设计约束）

- **模型名大小写这件事，本仓已经认过账。** `src-tauri/src/spend.rs:1476-1482` 的 `split_models`
  做了大小写不敏感前缀匹配，注释写明理由：「网关同一个 family 两种拼法（`qwen3.8-max` /
  `Qwen/Qwen3-235B`），大小写漏了会把行挂到错的卡上」。定价侧漏了同样处理 → 同一缺陷类第二次出现，
  按 owner 的既定要求必须建共享机制并核完所有实例，不许再打单点补丁。
- **「窗口未起步」的判定已经存在，但只覆盖一处半。** `src/main.ts:2434-2455` 的 `notStarted` 条件是
  `period_ms <= 6 * 3_600_000 && used <= 1`：只到 6 小时档，且是前端局部变量。概览环
  （`main.ts:4809` → `:5233-5243`/`:5286-5293`）、折叠卡徽标（`:3413` → `nearestResetSeconds`
  `:2782-2815`，只筛 `resets_at !== null` 不看用量）、悬停（`:2982-2984`）三处各自取 `resets_at`。
  `httpapi.rs:204`/`:215` 原样输出 `resetsAt`，外部消费者拿到的是未过滤结论。
- **`needs_setup` 第四态已经存在并且渲染成黄色而非红色**（`providers/mod.rs:280`，用例
  `providers/stepfun_plan.rs:146-157`、`providers/kimi.rs:236-237`/`:314-319`）。智谱这条不需要新
  状态、不需要新 UI，只需要走已有范式。
- **遍历护栏也已经存在一份完整的**：`spend.rs:826`（深度 16）、`:830`（目录数 20000）、
  `:895-937`（canonical 去环）。dsh 的 `dsh_data()` 内嵌 `scan()`（`:1764-1777`）是第二份手写遍历，
  三件套全无。
- **两种容错口径**：普通文件走 `from_utf8_lossy` + 坏行跳过（`spend.rs:1063`）+ 游标只在完整行推进
  （`:1060-1062`）；zstd 走 `decode_all(...).ok()?` + 严格 `String::from_utf8(...).ok()?`
  （`:1076-1078`），任一失败整文件返回 `None`，且 `Some(0)` 意味着压缩文件不参与增量续读。
- **上游同类修复的口径可以直接引用为设计依据**：#8413（查价不区分大小写）、#8631（用量为 0 的窗口
  不显示重置时间）、#8465（无套餐回落余额）。它们是独立产品在同一问题上收敛出的同一答案。

## Solution

五张票，彼此独立，可并行；只有 01 与 02 需要在实现前先做一次「全仓同类实例清点」。

| 票 | 一句话 | 优先级 | 量 |
|---|---|---|---|
| 01 | 模型名归一收成一个共享函数，定价与来源两侧共用 | P1 | 小 |
| 02 | 「窗口未起步」提成 metric 级标志，五个表面消费同一个结论 | P1 | 中 |
| 03 | 智谱无套餐回落余额，走已有 `needs_setup` 范式；顺带火山的凭据类型提示 | P1 | 中 |
| 04 | dsh 换用主遍历，删掉第二份手写递归 | P1 | 小 |
| 05 | zstd 与普通路径容错口径统一（lossy + 坏行跳过），并明确它是否进增量 | P2 | 小 |

## User Stories

1. 作为看 Codex weekly 窗口的人，我要**没动用过的窗口不要给我跳回满窗的倒计时**，这样我知道那一档
   还是满的而不是「还剩 7 天」。
2. 作为只订阅按量付费的智谱用户，我要卡片显示余额而不是红点，这样我不会以为 Pane 或我的账号坏了。
3. 作为用网关/第三方客户端的人，我要带大写的模型名照样算出钱，这样我不用手动维护 override 才发现没生效。
4. 作为让 Pane 常驻一天的人，我要任何一个来源的日志布局异常都**不会把整个进程挂死**。
5. 作为看消耗曲线的人，我要「某家某天真的是 0」和「某家某天读不出来」在界面上不是一回事。

## Implementation Decisions

- **不引入新依赖、不改存储格式。** 五票全部是既有代码路径的收敛。
- **01 的归一函数放在 `pricing.rs` 还是共享模块，取决于清点结果**：若 `spend.rs` 的
  `split_models` 语义（前缀匹配）与定价侧语义（精确查表）不同，则共享的是**归一化后的键**
  （小写 + 去空白 + 分隔符统一），不是匹配算法本身。先写清点，再定落点。
- **02 的标志位落在 Rust 侧**（`pace.rs` 的 `attach` 处写进 `Metric`），理由是 `httpapi` 必须一起受益；
  只在前端补 if 会让 `/v1/usage` 继续输出未过滤的 `resetsAt`，等于把同一个错留第二遍。
- **03 不新增 Snapshot 状态**，复用 `needs_setup`；若智谱余额端点确实不可用，宁可显示
  「无该套餐，且余额查不到」的黄色态，也不回落到红点。
- **04 直接调用 `recent_log_files`**，不给 dsh 加参数化护栏副本。
- **05 若决定让 zstd 进增量**，需要一并处理 `Some(0)` 的返回值语义；否则本票只统一容错，把增量留作
  显式不做，并在票里写清。
- **行号会漂。** 主 agent 正在改 `spend.rs` / `pricing.rs` / `main.ts`，开工前每个落点用符号名重定位，
  不要按本文件的行号硬套。

## Testing Decisions

- 每票至少一个**能失败**的回归测试，测试名写清缺陷形态而不是修复动作。
- 优先用 `parse-tests` 夹具（它通过 `#[path]` 编译真实源文件），不为测试新增产品代码接缝。
- **瞬时状态不许要求 owner 等**：02 的未使用窗口、05 的坏字节文件都属于可造材料，复现步骤写在各票的
  「取证材料」小节，全部用临时目录 + 环境变量覆盖（`DSH_HOME`、`CODEX_HOME` 一类），
  **不许在 `%APPDATA%\Pane` 或用户真实数据目录里造环或坏文件**。
- 03 需要一类真实账号（只有按量付费、没有 Coding Plan 的智谱 key）。若 owner 手上没有，本票只以
  夹具验收，真实账号那条勾保留未验证状态，不假装通过。

## Out of Scope

逐请求账本精度类，全部排除，理由见 Problem Statement：

- Codex `<threadId>_<rolloutId>` 分段续写在分段边界多计一条请求；子会话门控无超时兜底。
- MiniMax Code 模型名为空时回查同会话找回（上游 v4.0.16 的做法）。
- Codex 首行 `session_meta` 损坏导致父历史重复计入。
- 31 天以外的 Codex 历史读 cc-switch rollup 聚合：那是借来的二手显示，精度不承诺，不标记、不跟进。
- 上游新修但 Pane 本来更好的：扫描节奏、查价 memo、跨夏令时日期窗口、Codex 远程压缩双记录、
  Pi 子代理递归覆盖。
- 把 cc-switch 的本地路由/代理通道、SQLite + 不可逆剪枝、`AppType` 平铺布尔注册表搬进 Pane。

## 验收流程（给主验证的人）

目标是**半小时内把五票的上下文和材料核完**，不需要重新做调研。

### 第 0 步：确认边界（2 分钟）

本轮**只碰** `.scratch/dashboard-correctness/` 与公开 issue #48。不动 `spend.rs` / `pricing.rs` /
`main.ts` 的当前未提交改动；开工前先 `git status` 确认 reference-borrowings 批次是否已收尾，
未收尾就只审文档不改代码。所有行号都是 2026-10-23 工作区现状，**用符号名重定位，别按行号硬套**。

### 第 1 步：核「这是不是真缺陷」（每票 2–3 分钟，只需读一处代码）

| 票 | 打开这里 | 一眼要看到的证据 |
|---|---|---|
| 01 | `pricing.rs:628-634` 与 `spend.rs:1476-1482` | 定价侧原样字符串查表；来源侧已经为同一问题做过大小写折叠并写了理由 → 同类第二次 |
| 02 | `main.ts:2434-2455` 与 `main.ts:2782-2815` | 前者条件里写死 `<= 6 * 3_600_000`；后者筛 resets_at 时**完全不看用量** |
| 03 | `providers/zai.rs:149-166` | `DomainErr::Empty` 分支是 `{}` 空吞，最后落到 `unexpected quota response shape` |
| 04 | `spend.rs:1764-1777` | 裸递归 `if path.is_dir() { scan(...) }`，无深度/无环；对照 `:826`/`:830`/`:895-937` 那份完整护栏 |
| 05 | `spend.rs:1076-1078` 与 `:1063` | 压缩路径严格 `from_utf8(...).ok()?`，普通路径 `from_utf8_lossy` |

任一条对不上（代码已移动或已被别的会话改掉），在该票 Comments 里写明，不要推测。

### 第 2 步：核「材料是否真的齐」（不需要跑起来）

- 01、02、05 的取证与回归全部可在 `parse-tests` 夹具内完成，**不需要真实账号、不需要等瞬时状态**；
- 04 的复现靠 `DSH_HOME` 指向临时目录（`spend.rs:1782`），05 靠 `CODEX_HOME`（`:2351`），
  两者都不碰用户真实数据；04 的 junction 清理命令已写在票里，**必须用 `cmd //c rmdir`，不能 `rm -rf`**；
- **只有 03 需要外部材料**：一个「只有按量付费、没有 Coding Plan」的智谱 key，且需要先探到余额端点。
  owner 没有这个账号时，03 只以夹具验收，真实账号那条勾保持未验证。

### 第 3 步：核 owner 目检项（只有两项，其余都不该要求人等）

1. **02**：找一个未使用的 weekly/monthly 窗口，卡片、概览环、折叠卡徽标、悬停四处都不显示倒计时；
   再 `curl http://127.0.0.1:6736/v1/usage` 确认同一结论（这一条是「五处一致」的机器证据）。
2. **01**：用量面板里一个带大写的模型名出金额，不是 `unpriced`。

03 若拿到了合适账号，加一项：卡片不亮红点。04、05 无可视变化，只确认各家数值不回归。

### 第 4 步：核「范围有没有被偷偷扩大」

对照本 spec 的 **Out of Scope** 一节。若交付里出现了 Codex 分段续写、门控超时、MiniMax 模型名回捞、
cc-switch rollup 标记这类改动，属于越界——**那是逐请求账本精度，不是看板精度**，退回另开票。

### 五票之间的顺序

彼此独立可并行。若要串行，建议 **04 → 05 → 01 → 02 → 03**：先做两条改动量小、能立刻消除挂死与静默归零
的 Pane 自有缺陷，再做大写归一，02 需要先做一次取证所以放后面，03 卡在外部材料上放最后。
