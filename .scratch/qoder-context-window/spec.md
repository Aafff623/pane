# Qoder 0.4.9 窗口回退（qoder-context-window）

Status: 01/02/04 implemented; 03 awaiting owner decision
Source: GitHub #37（回归自 #28）；owner request 2026-10-22
Branch: `codex/qoder-context-window`（计划，尚未创建）

## Problem Statement

Qoder CN 0.4.9 更新后，桌面端转录里的 `runtime-config.contextWindow` 变成
`null`，Pane 的 Qoder 转录账本因此无法继续折算新请求的计费输入 tokens。
用户看到的是：credits 和请求次数还在增长，Qoder 的 token 总量却停在更新前；
2026-10-22 当天约 855 笔请求、按同模型 1M 窗口估算约 233M tokens 没有进入面板。
这不是网络、刷新、配置或插件问题，而是 Pane 对一个上游数据格式变化的容忍度不足。

## Solution

Pane 继续以 Qoder CN 本地转录为唯一账本，但把“窗口解析”做成一个明确的、按模型
隔离的回退链：转录里的非空窗口优先；同一模型最近一次非空窗口次之；仍然未知时，
只读查询 Qoder CN 自己保存的模型偏好窗口；最后才把 tokens 标为不可用。

用户仍然看到精确的 credits、准确的请求次数和带“估算”标记的 tokens；不会因为
窗口缺失而出现伪造的 0，也不会把某个模型的窗口套到另一个模型上。新会话即使从
第一条 `runtime-config` 起就是 `null`，也能在 Qoder 配置了窗口时恢复 token。

## User Stories

1. 作为 Pane 用户，我要 Qoder 更新后新产生的请求继续计入 token 用量，这样我当天的用量面板不会停在更新前的数字。
2. 作为 Pane 用户，我要 credits、请求次数和 token 三者的口径保持分离，这样 token 缺失时我不会误以为 credits 也不准。
3. 作为使用多个 Qoder 模型的用户，我要每个模型使用自己的上下文窗口，这样 1M 窗口的模型不会被套上别的模型窗口而虚高或虚低。
4. 作为刚在更新后新建会话的用户，我要即使整场会话只有 `null` 窗口，也能从 Qoder 的模型配置恢复 token，这样新会话不会从第一天就缺数据。
5. 作为使用子代理的用户，我要子代理继承父会话已经解析出的窗口，并且同一请求不重复计数，这样子代理消耗不会被漏算或重复算。
6. 作为使用未知模型或未配置窗口的用户，我要 tokens 明确显示为不可用，而不是伪造 0，这样我知道这块数据确实缺失。
7. 作为关注数据可信度的用户，我要回退得到的 token 仍然标为“估算”，并能看出窗口来自转录、最近已知值还是 Qoder 模型配置，这样我不会把估算当成实测。
8. 作为使用英文或俄文界面的用户，我要新增的窗口来源说明有对应翻译，这样我不会在非中文界面看到硬编码中文。
9. 作为开发者，我要窗口解析只有一个内部入口，主会话和子代理走同一套规则，这样修复不会在两个分支里分叉。
10. 作为开发者，我要 Qoder 数据库读取是只读、按扫描缓存、失败可降级的，这样我不会写坏 Qoder 的文件，也不会让一次锁库拖垮整个面板。
11. 作为开发者，我要窗口缺失时 credits 仍然精确、`tokens_unavailable_trips` 仍然计数，这样现有账本语义不被破坏。
12. 作为维护者，我要有覆盖“已知窗口 → null → 请求”“整场只有 null”“模型切换”“子代理继承”“数据库缺失/被占用”的 fixture，这样下次 Qoder 再改格式时能快速定位。
13. 作为维护者，我要现有 Qoder 会话发现、请求去重和 31 天扫描窗口保持不变，这样这次修复不会改变历史统计口径。
14. 作为 owner，我要面板能在不迁移数据、不重扫历史、不写 Qoder 文件的前提下恢复当天缺失的 token，这样修复可以直接在当前机器验收。
15. 作为隐私敏感用户，我要 Pane 只读取 Qoder 的模型窗口配置，不读取或上传会话正文之外的额外数据，这样本地账本的隐私边界不变。

## Implementation Decisions

- 窗口解析采用固定顺序：请求时生效的非空转录窗口 → 同一模型在本会话（含父会话）最近一次非空窗口 → Qoder CN 模型偏好中的该模型窗口 → 不可用。
- `runtime-config` 的 `null` 只能表示“这次没有新窗口”，不能清空同一模型已经知道的窗口；不同模型之间绝不互相回退。
- Qoder CN 模型偏好通过只读适配器读取，关键字段是模型键与上下文窗口；适配器按一次扫描缓存，数据库不存在、被占用或字段缺失时静默降级，不 panic、不写库、不迁移。
- BYOK 模型配置表不是本次修复的必要条件；如果后续需要支持 BYOK 的自定义窗口，再复用同一个适配器扩展，不在本 spec 里承诺。
- 报告层保留 credits 精确值、请求次数和 `tokens_unavailable_trips`；新增的窗口来源信息只服务于展示与诊断，不改变 token 的计算公式。
- 面板继续把 Qoder tokens 标为“估算”；当某个模型的 token 使用了回退窗口时，Qoder 明细/提示中要能指出窗口来源，不能把回退值伪装成转录实测值。
- 只引入一个内部窗口解析 seam，主会话与子代理共用；不为这次修复新增公共 API、配置项或迁移脚本。
- 不改变 Qoder 会话发现、子代理文件发现、`request_id` 去重、31 天扫描窗口，也不改变 credits/美元/额度总览的任何口径。

## Testing Decisions

- 好测试的标准：只验证 Qoder 账本的外部行为——每个模型的 `billed_tokens`、`tokens_unavailable_trips`、credits 和请求次数；不测试内部函数名或实现细节。
- 主要测试面在 Qoder spend report：用合成转录 fixture 覆盖窗口解析、模型隔离、子代理继承和去重。
- 数据库适配器用临时 SQLite fixture 测试：正常窗口、`NULL` 窗口、缺表/缺列、数据库不存在、数据库被占用；不访问网络。
- 先例：现有 Qoder 转录测试已经覆盖“请求时生效窗口”“子代理继承父窗口”“request_id 跨主/子转录去重”“真实机器快照（ignored）”，新测试沿用同一 harness 和断言风格。
- UI 若把窗口来源做成纯格式化逻辑，补一个纯函数单测；完整面板交互仍由 owner 在真机验收。

## Out of Scope

- 重新启用 Qoder CN 额度卡；它当前在 Pane 配置里被禁用/移除，是独立问题。
- 04 只做当前 31 天扫描窗口内的重新计算；不重写旧转录、不迁移数据，
  已删除且没有转录的会话仍不可恢复。
- 修复 `token-usage` 或 `qoder-credit-watch` 插件自己的数据源；Pane 不读取它们的输出。
- 写入 Qoder 数据库、配置或登录态；不向上游提交补丁。
- 任何全局或固定 200K 窗口回退；任何跨模型窗口借用。
- 历史回填、重写旧转录或新增后台迁移任务；修复只影响当前扫描窗口内的派生结果。
- BYOK 自定义窗口的完整支持、美元换算、credits 与 tokens 的固定汇率。
- 多设备/云端 Qoder 用量合并。

## Further Notes

- 现场证据（2026-10-22）：更新前最后一条非空窗口为 `dfmodel=1000000`；更新后 106 条 `runtime-config` 全为 `null`；同一会话的 Qoder 日志仍记录 `contextWindow=1000000`；Qoder CN 的模型偏好仍保存 `dfmodel` / `qfmodel` / `qmodel_38max = 1000000`。
- 当天复算：面板 Qoder 部分约 651M tokens，缺失 855 笔、约 233M tokens；恢复后约 884M（估算）。
- Qoder 可能是有意调整，也可能是 0.4.9 漏写；本 spec 的修复不依赖判断其意图，只要求 Pane 对窗口缺失保持可恢复和可解释。
