## Problem Statement

1. 工坊里每个皮肤的预览是两张 ~400px 宽的迷你卡并排，缩略图过大，一屏放不下几个皮肤，也没有导航侧边栏。
2. 皮肤资产（signal 全套 + ink 4.1MB）经 Vite import **硬打包进程序**，与"保持程序精简"冲突；用户没有选择权。
3. 工坊预览样张是手绘结构（signal-spend 大数字等），**不是真实卡片组件**，与实际应用的皮肤观感存在差异；用户要求预览（含亮暗兼容模式）的字体与 UI 组件和真实主题**完全一致**。
4. 官网的皮肤演示视图必须与本地一致（当前靠源码构建 demo + 溯源闸门保证，改版后需重构建同步）。

## Solution

皮肤=**资源包**：程序出厂只带原生外观，工坊展示皮肤包目录；用户**先下载、后使用**（两步制），下载经校验落本地、热加载应用，全程不重启。工坊改为经典两级布局：左侧栏=皮肤列表（小缩略图+状态），右侧=选中皮肤的大预览（亮/暗/并排切换保留）。预览一律用真实卡片组件渲染（等比缩放的缩略图与原尺寸大预览同源），不再手绘样张。分发走官网 Cloudflare（worker 索引端点 + R2 存包）。官网 demo 随源码重构建保持 1:1。

## User Stories

1. As a 用户, I want 工坊一屏看到所有皮肤的缩略图列表, so that 快速浏览和比较而不被巨型预览占满
2. As a 用户, I want 侧边栏列出皮肤与应用状态, so that 我随时知道当前用的是哪款、还有哪些可装
3. As a 用户, I want 点选侧栏皮肤后在右侧看大预览（亮/暗/并排）, so that 应用前能仔细看清楚
4. As a 用户, I want 未下载的皮肤显示「下载」按钮, so that 我明确知道它还不在本机
5. As a 用户, I want 下载完成后按钮变「使用」, so that 下载与应用是两步、不误触
6. As a 用户, I want 使用中的皮肤显示标记并可恢复原生外观, so that 我能随时回退
7. As a 流量敏感的用户, I want 皮肤不占安装包体积, so that 程序下载和更新保持精简
8. As a 已选皮肤的升级用户, I want 老皮肤自动迁移为资源包, so that 升级后我的主题不丢
9. As a 离线/下载失败的用户, I want 自动回退原生外观并在工坊看到提示, so that 应用永远可用
10. As a 用户, I want 工坊预览的字体和组件与真实主题一模一样, so that 我看到什么、用上就是什么
11. As a 亮暗混用的用户, I want 亮暗兼容模式预览同样与真实主题一致, so that 两种外观都不踏空
12. As a 访问官网的用户, I want 官网皮肤演示与本地应用完全一致, so that 下载前所见即所得
13. As a 分享 PNG 的用户, I want 资源包皮肤照样能导出带皮肤的分享图, so that 功能不因资源包化回退

## Implementation Decisions

### 工坊布局与两步制（票 01）

- 工坊改为侧栏+预览区两级布局：侧栏为皮肤条目（缩略图≈真实卡片等比缩小、名称、状态标记：使用中/已下载/未下载），右侧为选中皮肤的大预览区（保留亮/暗/并排三种预览模式切换），动作按钮在预览区下方。
- 按钮三态：未下载→「下载」；已下载→「使用」；使用中→禁用态「使用中」+「恢复原生外观」。
- 下载进度在按钮内联呈现，失败可重试；下载不阻塞工坊其他操作。

### 预览一致性（票 02）

- `renderSkinSample` 手绘样张退役：预览（缩略图与大图）改用**真实组件树**（provider 卡 + 现行 `renderMetric` + 固定示例数据，不读账号数据），在皮肤 CSS scope 下渲染。
- 预览应用皮肤的全部外观定义，含专配字体（资源包字体在预览上下文生效）；亮暗模式按现有外观设置与预览模式切换。
- 缩略图与大图同源：同一组件树、不同缩放，杜绝两套渲染。

### 资源包格式与加载（票 03）

- 包格式：zip；内含 `manifest.json`（id、名称、版本、minAppVersion、入口 CSS、资产清单、每个文件的 sha256）+ 资产文件。
- 安装位置：`%APPDATA%\Pane\skins\<id>\`；应用即切换皮肤命名空间（现 `data-skin` 机制延伸到动态包）。
- 热加载：CSS 动态注入、资产经 Tauri 资产协议解析，应用/切换/恢复原生全程不重启；字体经 @font-face 指向本地资产。
- 分享 PNG 的 `embedSkinImages` 适配包资产（本地文件 → data URL，沿用现有内嵌思路与安全边界：只嵌本机已装包资产，绝不抓远程）。
- 安全校验：只接受官方源索引列出的包；解压前后校验 sha256；manifest 不合法整包拒装。CSS 注入范围限定皮肤命名空间。

### CF 分发渠道（票 04）

- 官网 worker 新增皮肤索引端点（列出包 id、版本、大小、sha256、下载地址），包文件存 Cloudflare R2。
- 客户端工坊启动时拉索引（缓存 + 失败用上次索引），展示可下载列表。
- 版本更新检测展示为「有新版本可更新」，本期做提示与重装，不做后台静默更新。

### 全量出包与迁移（票 05）

- signal（云端邮局）与 ink（山水笺）资产全部从程序内拆出为资源包；程序内置仅原生外观；安装包相应瘦身（ink 资产 4.1MB + signal 资产不再入包）。
- 迁移：升级后首次启动检测已选皮肤不在内置 → 自动静默下载一次并应用（校验通过才切换）；失败回退原生外观并在工坊给出可重试提示。
- 原有"未知皮肤记录首次读取清除"逻辑延伸到资源包时代（包被删除时同样回退原生）。

### 官网同步（票 06）

- 以上全部落地后重跑 demo 构建（build-demo.mjs），溯源闸门保证 demo 与源码一致；官网皮肤演示视图随之与本地 1:1。
- 若官网存在手写的皮肤介绍图/文案，替换为 demo 截图或与真实渲染一致的素材。

## Testing Decisions

- 包格式、校验、索引解析、安装路径解析等纯逻辑 → parse-tests 既有 seam（参照 zcode_weekend 的纯函数+单测模式）。
- 工坊布局与两步交互 → tsc/vite 门禁 + temp/preview fixture 截图 + 用户亲自 UI 验收（本仓惯例，agent 不代验收）。
- 预览一致性 → 预览与真实卡片同组件树的代码结构保证 + 截图对比证据；工坊预览不读账号数据（沿用 T-0034 边界）。
- worker 端点 → site.test.mjs 既有测试面扩展。
- 迁移路径 → 模拟"已选皮肤+空包目录"的本地状态验证回退与自动下载（单测 + 手动各一轮）。

## Out of Scope

- 第三方皮肤的上传、审核、签名体系（只分发官方制作的包）。
- 付费/积分购买皮肤。
- 包的后台静默自动更新（本期只提示）。
- 皮肤影响 provider 数据/账号/额度行为的任何能力（T-0034 边界不变：主题只改表现）。
