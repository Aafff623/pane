# Pane 的 coss UI 迁移

Status: ready-for-agent

## 问题

Pane 的弹窗、表单和菜单各自处理状态、键盘与样式。用户跨页面遇到不同的操作反馈，维护时同类问题需要分开修。

## 产品结果

用 coss UI 做通用控件底座，逐步统一按钮、输入、选择、菜单和弹窗。默认主题升级控件、间距和视觉层级。用户仍从熟悉的入口找到数据和操作。

## 用户故事

1. 使用服务商帮助时，我能看到来源、接入步骤和检测结果，并用键盘打开、操作和关闭。
2. 在设置里切换时间格式后，看板立即显示选定格式，重启和恢复默认时读取同一个配置值。
3. 从浮窗打开菜单时，菜单随缩放和可用空间定位。
4. 编辑账号或取消授权时，能够看清结果并安全退出，过期请求不会盖掉最新操作。
5. 使用官方皮肤时，迁移后的控件仍沿用皮肤、字体及主题。自定义皮肤及配置继续保留，依赖内部选择器的样式按可取得的具体包验证。
6. 使用网站 Demo 时，可体验同一套布局。分享导出的 PNG 保持可读。
7. 维护 Pane 时，我可以从实际使用入口验证每个切片并清理已下线的专用实现。

## 实施决定

- 在现有 Tauri + Vite 前端渐进挂载 React。按需引入 coss Dialog、Button、Collapsible、Radio Group、Menu 及后续用到的组件。Tailwind 只引入新组件样式需要的工具类，不启用全局 Preflight。
- 继续使用现有配置、IPC、文案资源、图标和视觉变量。以 oil-ui-pro 的桌面工作区原则打磨控件，以 oil-art-landing 的色彩节制、层次和材质方法校准品牌表达。功能弹窗的主角是实际信息与操作。
- 已有视图入口、数据口径和用户配置格式维持原产品行为。每个切片替换自己的旧实现，保留其他调用方仍在使用的代码及原有有效注释。成熟的共同需求出现后再抽象。
- 只在边界校验与呈现外部失败。内部错误直接暴露。现有未提交改动单独备份并保留在原工作区，正式合入前核对重叠。
- 第一批帮助弹窗和时间格式交付真机验收，之后按 tickets 的真实依赖推进。Git 交付按仓库验收与授权约定执行。

## 验收

- 每个切片从实际入口运行。前端构建和相关回归通过。影响共享前端时构建并测试 Demo。
- Windows WebView2 覆盖默认及窄窗口、非默认缩放、快捷键唤起和失焦恢复、键盘 Tab/Esc 和焦点归还。主题覆盖浅深及三款官方皮肤，文字覆盖产品支持的语言。
- 账号相关切片用测试数据验证失败、取消及迟到结果。改到分享卡片时检查实际 PNG。
- 记录现状和迁移后同口径的首屏资源体积。只有实现变化确实让原断言失效时，才将回归断言移到可观察行为。

## 范围

Pane 桌面端通用界面组件与页面外壳，以及共用前端的 Demo 构建。看板整体信息组织、网站营销页重做和 Rust 业务改造另立需求。


## 设置与官网的视觉更新

- 按用户确认扩大视觉范围。设置加载画面、导航选中、搜索定位、常规设置分组及服务商字母索引一起更新。相关操作与原有配置结构保持兼容。
- 官网中英文首页更新首屏及主要内容区的视觉层级。实际面板演示、下载链接和公开产品事实沿用现有来源。浏览器验收小屏和中英文两条路径，正式发布另行授权。
