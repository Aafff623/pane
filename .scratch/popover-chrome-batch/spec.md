# 弹窗 chrome 批次：置顶 / 位置锁定 / 回到上次停留的界面

**Status:** implemented（1/1 票，2026-10-19；885:0:13、tsc/vite、51 node、
38 site 门禁全绿。**UI 验收待 owner**）

## Problem Statement

弹窗（popover）是 Pane 的主交互面，但此前它每次唤出都从同一个位置出现、
停在同一个界面。两个诉求：

1. **用户想自己决定弹窗在哪**。置顶（浮在其他窗口之上）与拖动位置是
   桌面软件的常规期待；位置被锁死时，用户每次打开都得再拖一次。
2. **用户想回到刚才在看的地方**。切到自定义看板、皮肤工坊，或某个
   provider 的配置页之后，去别处复制 API key 再按 Alt+2，之前一律跳回
   主界面、抽屉也关了（有用户反馈）。

## Solution

1. **chrome 放总花费行**：置顶（`popoverPin`）与锁定（`popoverLock`）两个
   按钮渲染在总花费卡头部、每日明细按钮左边——那行永远是最先看到的东西。
   面板表单窗口有自己的边框，不给 chrome。
2. **锁定默认开**：`popoverLock` 默认 `true`，此时每次唤出重新居中、
   不可拖动。解锁后整个窗口成为拖拽区域（按钮与输入框仍吞掉拖拽，卡片
   排序的 grip 单独退出拖拽），拖到的位置由 Rust 在弹窗消失时记下
   （`popoverPos`），下次唤出原位放回。重新锁定立刻弹回默认位置。
3. **置顶是窗口属性**：系统重启后不保留，每次唤出按配置重新设置
   `setAlwaysOnTop`。
4. **回到上次界面**：`lastView` = `{kind: main|customize|skin, id}`，切视图
   时写入，`popover-shown` 时恢复；关掉抽屉记 main。卡列表的滚动位置本来
   就记，两者合起来才是完整的「回到原地」。provider 已被删除时退回列表。

## 已知边界 / 待确认

- `popoverPos` 记的是物理像素坐标，换显示器分辨率后可能落在屏幕外——目前
  没有「位置越界时回退居中」的处理。
- 锁定状态的弹窗**不能**被拖动，但置顶与锁定可以独立组合（锁定+置顶=
  总是居中但浮在最上层）。
