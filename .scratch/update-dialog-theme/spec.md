## 3. 默认外观

采用不透明主题表面、轻边框和柔和外阴影，移除该弹窗默认外观中的玻璃渐变、多层内高光和徽章式星标。主按钮沿用 Pane 蓝色主题变量。

参考的逻辑尺寸为最大约 448 CSS px、14px 面板圆角、头部/正文/底部统一 24px 横向内边距。标题约 16px / 24px、600 字重；裸线条星光图标约 20px，与标题间隔 8px；正文约 13px / 20px。参考头部底部留白 12px，正文顶部留白 16px。按钮参考高 32px、6px 控件圆角。按实际宿主可用空间收缩，不能照搬截图约 760 个图像像素为 CSS 宽度。

星光图标左侧、副标题、版本号和分类标签共用内容区左边界。版本行右侧详情入口与底部确认按钮右边对齐。标签弱化为中性色，默认无新增绿/变更蓝/修复黄的强彩色描边。

头部与底部固定，正文按需滚动；底部与面板连续，无额外顶部分隔线或独立底色。按钮保持可见并可通过键盘访问。

修复 `#whatsnew-body ul` 对结构化摘要列表的 16px 左缩进覆盖。旧 Markdown 内容仍保留自己的列表排版，避免通过全局清空样式破坏日志和字体引导。

## 4. 摘要、版本与详情

- 更新成功摘要使用忠于事实、面向用户的简短句子。技术细节保留在完整日志，不通过随意截断或丢失限定条件制造短文案。
- 原图只有一版四条是本次升级区间与内容造成的，不是固定一版或四条的产品约束。多版本时按现有版本区间明确显示与展开，不静默隐藏内容。
- 版本行提供低干扰的真实详情入口。Pane 的日志在本地，优先复用本地浏览并定位对应版本，不虚构外链。
- 不改 CHANGELOG 的发布权威地位，不要求迁移为参考项目的 JSON 数据结构。
- 没有有效内容时沿用现有合理空态，不制造假的版本、更新条目或详情目标。

## 5. 主题与皮肤

统一信息结构、阅读顺序和对齐；外观材料、边框、阴影、字体层级及按钮随主题变化。

| 外观 | 要求 |
| --- | --- |
| 默认 | 实体面板、克制阴影、轻边框、中性标签、Pane 蓝色主按钮 |
| Signal / 云端邮局 | 延续纸张色、邮局描边和现有错位阴影，内部控件与外壳一致 |
| Ink / 水墨 | 延续宣纸/暗墨表面、墨线和低干扰纹理，正文保持易读 |
| Comic Pixel / 漫画像素 | 延续漫画边框、硬阴影和主题强调色，不整段使用像素正文 |

分别覆盖亮暗模式，共八种组合。覆盖面板、遮罩、标题、正文、次级文字、标签、图标、详情入口、按钮、悬停/按下/键盘焦点、滚动条与长内容状态。尊重用户字体和减少动态效果设置。

三款皮肤已有弹窗外壳覆盖，应在现有选择器与变量体系上补齐，不另建平行主题系统。检查实际安装资源包；若需构建本地包用于验证，必须与上传、发布严格区分，不能仅改源 CSS 就声称安装端生效。

## 6. 非目标与兼容性

不重做检查更新、下载或安装进度界面；不改更新端点或自动更新流程；不重构其他弹窗或引入 UI 框架。

保留首次启动、版本范围、已读记录、通知队列、完整日志和字体引导行为。参考没有右上角 ×、阻止遮罩点击关闭，但用户尚未单独选择改变 Pane 的关闭行为；此次默认保留既有行为。若确需改变，先解释影响并取得明确决定。

实施不包含提交、推送、打 tag、上传或发布授权。UI 验收由用户本人完成。

## 8. 验收标准

- 默认主题使用相近内容和相同视口/缩放与参考对照，检查构图、比例、三条对齐线及留白。
- 八种主题组合提供真实截图，无文字或按钮对比不足、残留玻璃底栏、皮肤穿透或切换残留。
- 验证短摘要、多版本、长条目、长内容滚动、窄窗口、焦点可见和操作按钮可访问。
- 首次启动、已读版本、队列顺序、完整日志与字体引导无行为回归。
- `pnpm build` 与相关前端/解析测试通过；非平凡改动完成代码审查和冗余检查，修复后重跑受影响检查。仅在确有 Rust 改动时按项目规范运行相应 Rust 检查。
- 未运行的检查写明未运行；源码分析不等于实机验收。最后由用户亲自验收，再决定后续交付。
